# 歌ってみた録音チェッカー

https://reccheck.40hzp.com

録ったボーカルのファイルを、MIXに出す前に確認するサイト。ファイルを選ぶと、形式・頭出し・音割れなどをその場で判定し、直し方を1行で返す。企画 40HzP。

- 解析はすべてブラウザの中で行う。**ファイルはどこにも送らず、保存もしない**
- 外部API・データベース・ログインは使わない。依存ライブラリも無い
- 歌の上手い下手・声質・表現は判定しない。見るのはデータの形だけ

---

## 判定項目と、しきい値の変え方

**判定項目・しきい値・判定の文言・出口のURLは、すべて `public/config.js` に入っています。**
数値や文言を直すときは、このファイルだけを書き換えれば足ります。

### 直し方（ブラウザだけで済みます）

1. https://github.com/40HzP/reccheck を開く
2. `public` フォルダ → `config.js` をクリック
3. 右上の**鉛筆マーク**（Edit this file）をクリック
4. 数値や文言を書き換える
5. 右上の緑の **Commit changes** ボタン → もう一度 **Commit changes**
6. 1〜2分待つと reccheck.40hzp.com に反映されます

数値の右にある `// 〜（仮）` は説明です。消しても動きますが、残しておくと次に見たとき迷いません。
**カンマ（`,`）や引用符（`"`）を消さないよう**気をつけてください。消すとページが動かなくなります。

### 判定の段階

| 段階 | 画面の表示 | 使う場面 |
| --- | --- | --- |
| 1 | そのまま送れます | 仕様どおり |
| 2 | 直すともっと良くなります | 仕様と違うが作業はできる |
| 3 | このままだと受け取れません | `/mix/guide` の「受けられないもの」に当たるときだけ |
| check | 確認してください | 自動では決められないもの（頭出し） |
| skip | 確認できません | そのファイルでは見られない項目 |

段階を変えたいときは、`config.js` の各項目の `outcomes` の中にある `stage:` の数字を書き換えます。
たとえば m4a を「直すともっと良くなります」にするなら、`format` の `m4a` の `stage: 3` を `stage: 2` にします。

### 項目の一覧

いまのしきい値はすべて**仮**です。手元の良い素材・困った素材を入れて、感覚と合うように合わせてください。

**どのMIX師に出すときも共通**

| 項目 | 見るもの | そのまま送れます | それ以外 | `config.js` で変える数値 |
| --- | --- | --- | --- | --- |
| 中身 | 長さと全体の音量 | 音が入っている | 短すぎる・ほぼ無音・途中で切れている＝段階2 | `minDurationSec`（10秒） / `silentPeakDb`（−50） |
| 頭出し | 冒頭の無音と、伴奏との長さの差 | 出さない（下の注記） | 下の表 | `immediateStartSec`（1秒） / `shorterThanInstSec`（5秒） / `sameLengthSec`（1秒） / `voiceDb`（−40） |
| 音割れ | 最大値に張り付いて続くサンプル | 見つからない | ある＝段階2 | `minRunSamples`（4） / `minCount`（1） / `ignoreBelowDb`（−12） |
| 音量の余裕 | いちばん大きいところ | −18〜−3dBFS | 小さすぎ・大きすぎ＝段階2 | `minDb`（−18） / `maxDb`（−3） |
| ノイズ | 歌っていないところの音量 | −60dBFS 以下 | 大きい＝段階2 | `maxDb`（−60） / `percentile`（10） |

**40HzPに出すなら**

| 項目 | 見るもの | そのまま送れます | それ以外 | `config.js` で変えるもの |
| --- | --- | --- | --- | --- |
| ファイル形式 | ファイルの先頭の数バイトと拡張子 | wav | mp3・圧縮wav・その他＝段階2 / m4a＝段階3 | 各 `outcomes` の `stage` |
| サンプリング周波数 | wav のヘッダ | 48kHz | 44.1kHz など＝段階2 | `okHz`（`[48000]`） |
| ビット深度 | wav のヘッダ | 32bit float / 24bit | 16bit など＝段階2 | `ok`（`["32bit float", "24bit"]`） |
| チャンネル | ヘッダと左右の差 | モノラル | ステレオ＝段階2（左右同じ／片側だけ／左右で違う、を書き分ける） | `sameDb`（−50） / `oneSideDb`（−40） |

**頭出しの出し方**

頭出しが「合っている」ことは自動では確かめられません（ボーカルに伴奏が入っていないので、位置を照らし合わせる手がかりが無い）。そのため「そのまま送れます」は出さず、典型的な失敗だけを拾います。

| 状況 | 表示 |
| --- | --- |
| 声が先頭から1秒以内に始まる **かつ** 伴奏より5秒以上短い | 段階3「頭出しされていない可能性が高いです」 |
| 伴奏との長さの差が1秒以内 | 確認してください「長さは合っています。曲の先頭から書き出したかだけ確認してください」 |
| 伴奏より短い／長い（上に当たらない） | 確認してください（差の秒数を出す） |
| 伴奏なしで、声が先頭から1秒以内に始まる | 確認してください（イントロのない曲でなければ頭出しされていない可能性） |
| 伴奏なしで、冒頭に無音がある | 確認してください（無音の秒数を出す） |

見分けられないもの：数拍〜1小節のずれ／DAW上で伴奏を0秒以外に置いている場合。イントロの無い曲は「先頭から始まる」に引っかかるので、どれも断定しない言い方にしています。

### 見ていないもの・苦手なもの

- **wav 以外は形式だけ**を見ます（mp3 / m4a などは、長さや音量を見ません）
- **ケロケロ系のオートチューン**は自動では判定しません。結果の下に注意書きを1行出すだけです
- 音割れは「最大値に張り付いて平らになった波形」で見ています。マイクやプリアンプの段階で歪んだ音（デジタルの最大値に届いていない歪み）は見つけられません
- ノイズは、細かく区切った音量の小さいほうから10%のところを「歌っていないところ」とみなしています。ゲートやノイズ除去をかけて隙間を消したファイルでは、歌っていないところが見つからず「確認できません」になるか、静かに歌っているところを拾って大きめに出ることがあります
- 32bit float は 0dBFS を超えてもデータが残るので、「超えている（残っている）」と「張り付いて潰れている」を分けて出します

### 出口のURL

結果の下のボタンは `config.js` の `exits` にあります。MIX依頼は既存のUTM規約どおり `utm_source=reccheck&utm_medium=result` を付けているので、Discord通知の流入元に `reccheck / result` と出ます。

フッターのリンク（40HzP・声域測定・支援）は `config.js` の `footer` にあります。

## 構成

```
public/                  … ここの中身がそのまま公開される（ビルド工程なし）
  index.html             … ページの骨組み・タイトル・OGP
  style.css              … 見た目。色・見出しの段組みは 40hzp.com に合わせている
  config.js              … 判定項目・しきい値・文言・出口のURL（ここだけ直せば足りる）
  js/app.js              … 画面の動き
  js/analyze.js          … ファイルを分割して読み、数値を計る
  js/worker.js           … 解析を画面とは別の流れ（Web Worker）で動かす。大きいファイルでも画面が固まらない
  js/wav.js              … wav のヘッダとサンプルを直接読む
  js/sniff.js            … ファイルの先頭から形式を見分ける
  js/meter.js            … 最大値・張り付き・区間ごとの音量などを貯める
  js/judge.js            … 計った数値と config.js から段階と文言を決める
  favicon.svg / og.png   … タブのアイコン / リンクを貼ったときのプレビュー画像（1200×630）
test/                    … 自動テスト（公開はされない）
wrangler.jsonc           … Cloudflare Workers の設定。reccheck.40hzp.com への割り当てもここ
```

wav をブラウザ標準の音声デコード（Web Audio API）で読まないのは、再生用の周波数・32bit float に揃えられてしまい、元のサンプリング周波数とビット深度が分からなくなるためです。

ファイルサイズの上限は 300MB（`config.js` の `maxFileMB`）。5分・モノラル・48kHz・32bit float で約58MB。4MBずつ読むので、大きいファイルでもメモリを食いすぎません。

## 公開手順（初回のみ・クリックのみ）

神がとう診断と同じ構成です。

0. GitHub でこのリポジトリの既定ブランチを `main` にする（Settings → Branches → Default branch）
1. Cloudflare ダッシュボード → Workers & Pages → 作成 → 「リポジトリをインポート」でこのリポジトリを選ぶ
2. 設定
   - ビルドコマンド：空欄
   - デプロイコマンド：`npx wrangler deploy`
   - ブランチ：`main`
3. デプロイ。`wrangler.jsonc` の `routes` によって `reccheck.40hzp.com` が自動で割り当てられる
4. https://reccheck.40hzp.com を開いて表示を確認

以後は `main` に push するたびに自動で再デプロイされます。

### アクセス解析

Cloudflare Web分析（Cookieを使わない）をダッシュボードで有効にします。HPと同じく自動注入が効けばコード変更は不要です。
**HP・ボツ供養とは別サイト・別トークンとして登録**してください（数字が混ざらないように）。

### 公開するとき（検証が済んでから）

試作・検証のあいだは検索結果に出ないようにしてあります。公開するときは:

1. `public/index.html` の `<meta name="robots" content="noindex">` の行を消す
2. `40hzp.com/mix/guide` からリンクを1本張る
