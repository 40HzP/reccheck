# 歌ってみた録音チェッカー

https://reccheck.40hzp.com

録ったボーカルのファイルを、MIXに出す前に確認するサイト。ファイルを選ぶと、形式・頭出し・音割れなどをその場で判定し、直し方を1行で返す。企画 40HzP。

- 解析はすべてブラウザの中で行う。**ファイルはどこにも送らず、保存もしない**
- 結果の下の「記録する」を押したときだけ、判定の数値と機材名を匿名で記録する（Cloudflare D1）。押さなければ外部と一切通信しない（下の「記録」）
- 前回の結果はブラウザの中（localStorage）にだけ残し、もう一度確かめたときに並べて出す
- ログインは無い。依存ライブラリも無い
- 歌の上手い下手・声質・表現は判定しない。見るのはデータの形だけ

## 判定項目と、しきい値の変え方

**判定項目・しきい値・判定の文言・出口のURLは、すべて `public/config.js` に入っています。**
数値や文言を直すときは、このファイルだけを書き換えれば足ります。

### 直し方（ブラウザだけで済みます）

1. https://github.com/40HzP/reccheck を開く
2. `public` フォルダ → `config.js` をクリック
3. 右上の**鉛筆マーク**（Edit this file）をクリック
4. 数値や文言を書き換える
5. 右上の緑の **Commit changes** ボタン → もう一度 **Commit changes**
6. 1〜2分待つと reccheck.40hzp.com に反映されます

数値の右にある `// 〜（仮）` は説明です。消しても動きますが、残しておくと次に見たとき迷いません。
**カンマ（`,`）や引用符（`"`）を消さないよう**気をつけてください。消すとページが動かなくなります。

### 判定の段階

| 段階 | 画面の表示 | 使う場面 |
| --- | --- | --- |
| 1 | そのまま送れます | 仕様どおり |
| 2 | 直すともっと良くなります | 仕様と違うが作業はできる |
| 3 | このままだと受け取れません | `/mix/guide` の「受けられないもの」に当たるときだけ |
| check | システムでは判断しきれません | 自動では決められないもの（頭出し） |
| skip | 確認できません | そのファイルでは見られない項目 |

画面の表示は `config.js` の `stages` にあります。表示を変えたら、この表も合わせて直してください（下の表は段階の名前で書いているので直さなくて済みます）。

段階を変えたいときは、`config.js` の各項目の `outcomes` の中にある `stage:` の数字を書き換えます。
たとえば m4a を「直すともっと良くなります」にするなら、`format` の `m4a` の `stage: 3` を `stage: 2` にします。

### 項目の一覧

いまのしきい値はすべて**仮**です。手元の良い素材・困った素材を入れて、感覚と合うように合わせてください。

**どのMIX師に出すときも共通**

| 項目 | 見るもの | そのまま送れます | それ以外 | `config.js` で変える数値 |
| --- | --- | --- | --- | --- |
| 中身 | 長さと全体の音量 | 音が入っている | 短すぎる・ほぼ無音・途中で切れている＝段階2 | `minDurationSec`（10秒） / `silentPeakDb`（−50） |
| 頭出し | 冒頭の無音と、伴奏との長さの差 | 出さない（下の注記） | 下の表 | `immediateStartSec`（1秒） / `shorterThanInstSec`（5秒） / `sameLengthSec`（1秒） / `voiceDb`（−40） |
| 音割れ | 最大値に張り付いて続くサンプル | 見つからない | ある＝段階2 | `minRunSamples`（4） / `minCount`（1） / `ignoreBelowDb`（−12） |
| 音量の余裕 | いちばん大きいところ | −18〜−3dBFS | 小さすぎ・大きすぎ＝段階2 | `minDb`（−18） / `maxDb`（−3） |
| ノイズ | 声の無い区間（歌い出し前・フレーズの間・歌い終わり）の雑音 | −60dBFS 以下 | 大きい＝段階2 / 声の無い区間が無い・完全な無音しかない＝未測定 | `maxDb`（−60） / `marginSec`（0.3秒） / `minQuietSec`（1秒） |
| 部屋の響き（目安） | フレーズの終わりで声が消えていく速さ | 少ない・普通 | 多い＝段階2 / フレーズの終わりが3か所未満＝未測定 | `fastDbPerSec`（150） / `slowDbPerSec`（70） |

**40HzPに出すなら**

| 項目 | 見るもの | そのまま送れます | それ以外 | `config.js` で変えるもの |
| --- | --- | --- | --- | --- |
| ファイル形式 | ファイルの先頭の数バイトと拡張子 | wav | mp3・圧縮wav・その他＝段階2 / m4a＝段階3 | 各 `outcomes` の `stage` |
| サンプリング周波数 | wav のヘッダ | 48kHz | 44.1kHz など＝段階2 | `okHz`（`[48000]`） |
| ビット深度 | wav のヘッダ | 32bit float / 24bit | 16bit など＝段階2 | `ok`（`["32bit float", "24bit"]`） |
| チャンネル | ヘッダと左右の差 | モノラル | ステレオ＝段階2（左右同じ／片側だけ／左右で違う、を書き分ける） | `sameDb`（−50） / `oneSideDb`（−40） |

**頭出しの出し方**

頭出しが「合っている」ことは自動では確かめられません（ボーカルに伴奏が入っていないので、位置を照らし合わせる手がかりが無い）。そのため「そのまま送れます」は出さず、典型的な失敗だけを拾います。

| 状況 | 段階 | 本文 |
| --- | --- | --- |
| 声が先頭から1秒以内に始まる **かつ** 伴奏より5秒以上短い | 3 | 頭出しされていない可能性が高いです |
| 伴奏との長さの差が1秒以内 | check | 長さは合っています。曲の先頭から書き出したかだけ確認してください |
| 伴奏より短い／長い（上に当たらない） | check | 差の秒数を出し、曲の先頭から書き出したかの確認を促す |
| 伴奏なしで、声が先頭から1秒以内に始まる | check | イントロのない曲でなければ、頭出しされていない可能性がある |
| 伴奏なしで、冒頭に無音がある | check | 無音の秒数を出し、曲の先頭から書き出したかの確認を促す |

見分けられないもの：数拍〜1小節のずれ／DAW上で伴奏を0秒以外に置いている場合。イントロの無い曲は「先頭から始まる」に引っかかるので、どれも断定しない言い方にしています。

### 見ていないもの・苦手なもの

- **wav 以外は形式だけ**を見ます（mp3 / m4a などは、長さや音量を見ません）
- **ケロケロ系のオートチューン**は自動では判定しません。結果の下に注意書きを1行出すだけです
- 音割れは「最大値に張り付いて平らになった波形」で見ています。マイクやプリアンプの段階で歪んだ音（デジタルの最大値に届いていない歪み）は見つけられません
- ノイズは、声の無い区間だけで測ります。声のある区間は前後0.3秒ずつ広げてから外すので、息や響きの残りはほとんど拾いません。完全な無音（デジタルの0。ノイズゲートや編集の跡）の区間は計算から外し、外したことを結果に書きます。声の無い区間が無い、または完全な無音しか無い録音は「未測定」です
- 部屋の響きは、フレーズの終わりで声が消えていく速さ（dB/秒）の中央値から推した**目安**です。150dB/秒は響きが約0.4秒で消える部屋、70dB/秒は約0.9秒で消える部屋にあたります。作った音（響きの長さが分かっている音）では正しく当たることを確かめていますが、実際の歌は音の切り方（ゆっくり消すなど）の影響も混ざるので、手元の素材で合っているか確かめてください。響きが長い部屋では、残った響きがノイズとして少し大きめに出ることがあります
- 32bit float は 0dBFS を超えてもデータが残るので、「超えている（残っている）」と「張り付いて潰れている」を分けて出します

### 前回との比較

同じブラウザでもう一度確かめると、結果の下に「前回との比較」が出ます（形式・周波数・ビット深度・チャンネル・長さ・いちばん大きいところ・張り付いたサンプル・声の無い区間の雑音・部屋の響き）。前回から変わった行は、今回の値を太字にしています。

前回の結果はブラウザの中（localStorage）にだけ残り、外には送りません。並べる行と見出しは `config.js` の `compare` にあります。

### 出口のURL

結果の下のボタンは `config.js` の `exits` にあります。MIX依頼は既存のUTM規約どおり `utm_source=reccheck&utm_medium=result` を付けているので、Discord通知の流入元に `reccheck / result` と出ます。

フッターのリンク（40HzP・声域測定・支援）は `config.js` の `footer` にあります。

## 構成

```
public/                  … ここの中身がそのまま公開される（ビルド工程なし）
  index.html             … ページの骨組み・タイトル・OGP
  style.css              … 見た目。色・見出しの段組みは 40hzp.com に合わせている
  config.js              … 判定項目・しきい値・文言・出口のURL・記録の列（ここだけ直せば足りる）
  js/app.js              … 画面の動き
  js/analyze.js          … ファイルを分割して読み、数値を計る
  js/worker.js           … 解析を画面とは別の流れ（Web Worker）で動かす。大きいファイルでも画面が固まらない
  js/wav.js              … wav のヘッダとサンプルを直接読む
  js/sniff.js            … ファイルの先頭から形式を見分ける
  js/meter.js            … 最大値・張り付き・区間ごとの音量などを貯める
  js/voice.js            … 声のある区間と無い区間を分け、雑音と部屋の響きを推す
  js/judge.js            … 計った数値と config.js から段階と文言を決める
  js/store.js            … ブラウザの中にだけ残すもの（前回の結果など）
  js/record.js           … 「記録する」「このブラウザの記録を消す」
  favicon.svg / og.png   … タブのアイコン / リンクを貼ったときのプレビュー画像（1200×630）
worker/                  … 記録の受け口（/api/records）。D1 への書き込みと削除
scripts/export-csv.mjs   … 記録を CSV に書き出す
test/                    … 自動テスト（公開はされない）
wrangler.jsonc           … Cloudflare Workers の設定。D1 と reccheck.40hzp.com の割り当てもここ
```

wav をブラウザ標準の音声デコード（Web Audio API）で読まないのは、再生用の周波数・32bit float に揃えられてしまい、元のサンプリング周波数とビット深度が分からなくなるためです。

ファイルサイズの上限は 300MB（`config.js` の `maxFileMB`）。5分・モノラル・48kHz・32bit float で約58MB。4MBずつ読むので、大きいファイルでもメモリを食いすぎません。

## 公開手順（初回のみ・クリックのみ）

神がとう診断と同じ構成です。

0. GitHub でこのリポジトリの既定ブランチを `main` にする（Settings → Branches → Default branch）
1. Cloudflare ダッシュボード → Workers & Pages → 作成 → 「リポジトリをインポート」でこのリポジトリを選ぶ
2. 設定
   - ビルドコマンド：空欄
   - デプロイコマンド：`npx wrangler deploy`
   - ブランチ：`main`
3. デプロイ。`wrangler.jsonc` の `routes` によって `reccheck.40hzp.com` が自動で割り当てられる
4. https://reccheck.40hzp.com を開いて表示を確認

以後は `main` に push するたびに自動で再デプロイされます。

### アクセス解析

Cloudflare Web分析（Cookieを使わない）をダッシュボードで有効にします。HPと同じく自動注入が効けばコード変更は不要です。
**HP・ボツ供養とは別サイト・別トークンとして登録**してください（数字が混ざらないように）。

### 検索結果への表示

検索結果に出る設定です（試作・検証のあいだに入れていた `noindex` は外しました）。
告知はせず、`40hzp.com/mix/guide` からリンクを1本張って公開する方針です。

```html
<meta name="robots" content="noindex">
```

## 記録（結果と機材の匿名の記録）

機材ごとに「普通の部屋で録るとどうなるか」を貯めて、機材紹介とMIX依頼につなぐための記録です。録音のやり方に条件は付けません。記録しなくてもチェッカーはそのまま使えます。

- **送るのは「記録する」を押したときだけ**。押さなければ、ページは外部と一切通信しません（迷惑送信よけの Turnstile も、押したときに初めて読み込みます）
- 送るもの：判定の数値（形式・サンプリング周波数・ビット深度・チャンネル数・いちばん大きいところ・張り付いたサンプル数・声の無い区間の雑音・部屋の響き・長さ・項目ごとの段階）、機材の自由記述5欄（マイク・オーディオインターフェース・プリアンプ・ポップガード・部屋。各60字まで、空欄可）、前回から機材を変えたか（前回の結果があるときだけ聞く）、ブラウザの中で作った乱数ID、判定のしかたの版
- **送らないもの**：音声ファイル、ファイル名、IPアドレス、User-Agent
- 結果の下の「このブラウザの記録を消す」で、同じ乱数IDの記録をすべて消せます（このブラウザに残した前回の結果なども一緒に消えます）

PR のブランチは、Cloudflare が試し用の URL（Preview）に出します。試し用の URL にはデータベースを繋いでいない（`wrangler.jsonc` の `previews` が空）ので、そこでは記録できません。本番の記録に試しのデータが混ざらないようにするためです。

### 記録の列（1か所だけ）

記録の列は **`config.js` の `record.columns` だけ**に書いてあります。データベースの表はこの一覧から自動で作られ、ページ下部の「記録する内容」もこの一覧の `label` から出ています。別の SQL ファイルなどには書いていません。

- 列を**足す**ときは、`record.columns` の末尾に1行足すだけです。次に誰かが記録したときに、表にも自動で足されます
- 一度記録した列の**名前や kind を変えたり、消したりはしないでください**。前のデータと合わなくなります
- 判定のしかたの版（`app_version`）は「計算の版-設定の印」の形です。しきい値を変えると後ろの印が自動で変わるので、変える前と後のデータを区別できます（文言を直しただけでは変わりません）

### 記録の準備（初回のみ）

`record.turnstileSiteKey` が空のあいだは、記録の欄は画面に出ません。次の手順は 2026-11-14 に済んでいます（作り直すときのために残しています）。

**1. データベース（D1）** … 済み

初めてのデプロイで、`reccheck` という名前の D1 が自動で作られました。その ID を `wrangler.jsonc` の `database_id` に書いてあるので、以後のデプロイはこのデータベースに繋がります。デプロイのログにこう出ていれば繋がっています。

```
env.DB (reccheck)          D1 Database
```

データベースを作り直したとき（消してしまったときなど）は、繋ぎ直します。

1. Cloudflare ダッシュボード → **ストレージとデータベース** → **D1** → **作成**、名前は `reccheck`
2. 出てきた **データベースID** をコピー
3. https://github.com/40HzP/reccheck/edit/main/wrangler.jsonc を開き、`"database_id"` の中身をコピーした ID に差し替えて Commit
   **引用符 `"` は消さないでください。** 中身だけを入れ替えます

表は、次に誰かが記録したときに自動で作られます。

**2. 迷惑送信よけ（Turnstile）** … 済み

1. ダッシュボードの左メニュー **Turnstile** → **ウィジェットを追加**
2. 名前は何でも構いません（例：`reccheck`）。ドメインに `reccheck.40hzp.com` を入れて作成
3. 鍵が2つ出ます。**使い道が違うので混ぜないでください**

| 名前 | 人に見せて | どこに入れるか |
| --- | --- | --- |
| **Site Key** | よい | `public/config.js` の `record.turnstileSiteKey` |
| **Secret Key** | **絶対にだめ** | Worker のシークレット `TURNSTILE_SECRET_KEY` |

4. **Secret Key を先に入れます。** Workers & Pages → `reccheck` → **設定** → **変数とシークレット**（右側のリストの上のほう。「ビルド」の中のものではない）→ **追加** → 種類を**シークレット**にして、名前 `TURNSTILE_SECRET_KEY`、値に Secret Key
5. 最後に Site Key を `config.js` に入れて Commit。1〜2分で記録の欄が出ます

```js
turnstileSiteKey: "0x4AAAAAAA....",
```

Secret Key より先に Site Key を入れると、記録の欄は出ますが「記録できませんでした」になります（受け口が 503 を返す）。

### 記録を CSV に書き出す

Cloudflare の画面には CSV で書き出すボタンが無い（D1 の書き出しは SQL 形式のみ）ので、手元のパソコンから書き出します。Node.js（22以上）が要ります。

1. このリポジトリを手元に置く（GitHub Desktop などで clone）
2. そのフォルダで、初回だけ Cloudflare にログインする

```
npx wrangler login
```

3. 書き出す

```
npm run export-csv
```

同じフォルダに `records-20261114.csv` のような名前で出ます。Excel で開いても文字化けしないようにしてあります。CSV は git に入らない設定です（`.gitignore`）。

中身をちょっと見るだけなら、Cloudflare ダッシュボード → **D1** → `reccheck` → **コンソール**で `SELECT * FROM records ORDER BY id DESC LIMIT 50` と打てば見られます。

機材名は書いてもらったまま（`mic_raw` など）入っています。「SM7B」「sm7b」のような表記ゆれは、数が貯まってから CSV の上でまとめて揃える方針です。

## テスト

パソコンに Node.js（22以上）が入っていれば、次で判定と記録の受け口の自動テストが動きます。運用には不要です。

```
npm test
```

テスト用の wav はテストの中で作っています（`test/wavgen.js`）。記録の受け口のテストは、D1 の代わりに Node.js の SQLite を使い、Turnstile の照会は差し替えています。
